# SESSION-2026-09-29-1 — Auto-close shifts at configurable shift end time

## Objective
User reported: staff who punch in but forget to punch out are blocked from punching in the next day. Fix: auto-close all open shifts at a configurable shift end time (default 4 PM), with a notification pushed to the teacher.

## Env facts
- Supabase project: `hxkowdaugkkumvzyfsai.supabase.co`
- Git remote: `https://github.com/sectofficework-droid/SATYAM-SCHOOL.git`, branch `main`
- No Supabase CLI access token; service role key in `admin-panel/.env.local`

## Decisions & Design
1. **Single global `shift_end_time`** in `kiosk_settings` (not per-shift table) — simplest model, future-ready for multi-shift later.
2. **pg_cron** over Vercel cron — runs inside Postgres, no external dependency, works on free tier.
3. **No warning before auto-punch-out** — user explicitly said no warning needed, just push a notification after.
4. **Notification on both auto and manual checkout** — `teacher_alerts` insert in both `auto_close_open_shifts` and `record_check_out` RPCs.
5. **Migration split into two files** — core RPCs (safe) + pg_cron (may fail on free tier) so the core works even if pg_cron doesn't.
