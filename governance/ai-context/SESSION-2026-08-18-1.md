## Part 4 — password view→reset correction (same day, immediate follow-up)
User pushed back: "we have kept password view intentionally... if the user
comes to admin to view password or reset the admin can help them back." This
was a real product requirement I removed without offering the replacement.

**Root cause explained to user:** bcrypt hashing is one-way — once applied,
*nobody*, including the admin, can read an existing password back. That's
not a side effect, it's the entire point of hashing (the same readability
that let the admin "view" it is what would let a DB leak expose everyone's
real password). Viewing and hashing are mutually exclusive; asked the user
to choose between (a) reset instead of view, (b) revert Stage 1 entirely, or
(c) something else. User chose (a).

  `PasswordResetRow` (replaces the deleted `PasswordRow`): collapsed state
  shows a "Reset password…" link; expanded state has a password field +
  Generate (random 10-char) + Save, and after a successful save shows the
  new password once with a copy button and a "won't be shown again" note.
  Re-added `Copy` icon import (removed earlier this session, now needed
  again) + added `KeyRound`. Verified: `npx next lint` on both files again
  after this change — clean.
- `mobile-app/SUPABASE_PASSWORD_SECURITY.sql` — added
  `admin_reset_employee_password`/`admin_reset_student_password`
  (SECURITY DEFINER, hash the new password server-side, reset lockout
  state). Granted to `authenticated` only — explicitly NOT `anon`, so mobile
  clients can never call these. Each function also independently checks
  `EXISTS (SELECT 1 FROM admin_users WHERE id = auth.uid())` before allowing
  the update — same identity pattern `AuthGuard.jsx` already uses, so the
  RLS-bypassing SECURITY DEFINER privilege doesn't become a blanket door.
  Added a 5th manual verification step to the file's footer covering the
  reset flow + confirming a non-admin/anon caller is rejected.

  student equivalent existed) — did NOT build a new Student-facing reset

  wants that UI built later.
