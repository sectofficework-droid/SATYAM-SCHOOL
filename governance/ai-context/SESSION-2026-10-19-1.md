# SESSION 2026-10-19 (1) — Notebook module + marks report (REQ-FEAT-020)

## Objective
User asked to add a new "Notebook" module to the mobile Teacher app: a
per-class, per-date grid where every student's notebook-completion status
is ticked by default, teacher unticks incomplete ones, autosaves per cell.
Mid-session the user added a follow-up: each subject worth 10 marks per
tick, with a running total over different dates — a report, not a new
data field.

## Env facts
No change from `BOOTSTRAP.md`'s recorded environment. `flutter analyze`
and `npm run lint` both run clean this session (see below).

## Decisions (scope evolved live, each confirmed with the user before coding)
1. Picker scope: user first said "class teacher only" (homeroom-restricted,
   like Attendance), then explicitly corrected to "any teacher can select
   any class, no need of class teacher" — final behavior has no
   class-teacher restriction, same "any class" philosophy as Homework/
   Exams/Syllabus/Daily Log.
2. Grid shape: not a per-teacher subject picker like Daily Log — one grid
   per class+date with ALL of that class's subjects (from `class_subjects`)
   as frozen columns, students as frozen rows. User's exact words: "there
   will be only one table view per class where student name will be in
   column frozen and all subject will be in row header frozen."
3. Date: user first said "today only, no picker," then asked for a picker
   too ("also give the date piker if they want to select any other date") -
   final: defaults to today, picker-editable like Daily Log (60-day back
   window).
4. Autosave: every tap saves immediately via a single-cell upsert RPC - no
   batch Save button (unlike Daily Log).
5. Marks follow-up: no data-model change - marks (ticks × 10) computed on
   the fly from existing rows, shown in a new teacher-app report screen AND
   a new admin-panel report section (both requested).
6. REQ-FEAT-020, not -019: discovered mid-session that REQ-FEAT-019 was
   already used in-repo (`SUPABASE_STUDENT_IMPORT_PHASES.sql`, Student
   Import Phases) - renumbered before applying any migration.
