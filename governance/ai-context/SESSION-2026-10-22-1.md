# SESSION 2026-10-22 (1) — Batch Management + stop auto-creating batches (REQ-FEAT-021)

## Objective
User: admin panel was "creat[ing] unnecssary extra batch everytime i do
any students update" — asked for a batch management system in Settings,
and for the default to be "no batch" so nothing is created/added to a
batch unless selected manually. Mid-session, corrected the scope: the
batch picker should only appear on the import/replacement/new-entry
tools, not the single-student edit tools.

## Env facts
No change from `BOOTSTRAP.md`'s recorded environment. `npm run lint` ran
clean this session. Dev server (`npm run dev`) started and compiled every
touched route with zero errors, then stopped at session end.

## Decisions (scope evolved live, each confirmed with the user before coding)
1. Root cause, confirmed by reading code + live DB (not assumed):
   `BatchSelector.js`'s default `value` (`null`) mapped to `<option
   value="">+ Start New Batch</option>` — the empty string default landed
   on that option, not a "do nothing" option, because no such option
   existed. `recordPhase()` then always ran since every one of the 5
   call sites invoked it unconditionally. Live
   `student_import_phases` confirmed the effect: batches 1-5 genuine
   (`historical_backfill_ph1/ph2`, `replace_full_details` —
   30/16/26/30/3 students at first read), batches 6-18 all
   `edit_student_form`/1-student/all created 2026-10-22.
2. First bundled AskUserQuestion round (answered 2026-10-22): (a) default
   "No Batch" across **all 5** entry points — Add Student, Edit Student,
   Super-Admin Update Student, Import Students, Replace Full Details,
   Basic Details Import; (b) **delete** the 13 junk batches (6-18) rather
   than leave them or merge them; (c) Settings tab gets **all 4**
   requested capabilities (create+label, delete/remove-entry,
   move-entry, view+recompute).
3. User's own follow-up correction, same session: "the selection was
   mainly for import / replacement or new entry so batch selection should
   be show there." This **superseded** 2(a) — the two single-student edit
   tools (Edit Student page, Super-Admin "Update Student") don't just
   default to "No Batch", they lose the `BatchSelector` UI and the
   `recordPhase()` call entirely. Only Add Student, Import Students,
   Replace Full Details, Basic Details Import keep the (now 3-way,
   default-"No Batch") selector. Recorded this correction in
   `planning/TODO.md`'s REQ-FEAT-021 entry before touching any code
   (§J12B — MAJOR change, spec/TODO updated before implementation).
4. §J4/§J5 destructive-op disclosure given explicitly in-session
   (production server, affected tables, PII data loss, no automated
   backup → manual JSON dump taken first, no automated rollback) before
   running the DELETE on batches 6-18 — approval for that specific scope
   was already on record from decision 2(b) above.
5. The pre-delete JSON backup (13 phases + their single entries each,
   full snapshot data including Aadhar/phone/address) was written to
   `Scratch\SATYAM-SCHOOL\backups\` (git-ignored) rather than
   `governance\work-log\` — a tracked continuity folder should not carry
   raw student PII into git history; `Scratch/` is explicitly
   disposable/untracked prep material per AGENTS.md §A.2, which is the
   right fit for a recovery-only artifact like this.
