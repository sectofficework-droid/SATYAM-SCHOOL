## REQ-FEAT-025: Recurring reminder/call-back system (same session)
User asked for a "remainder section to call back again if submit date
passes away" plus a reminder button in the note section, popping up
repeatedly until dismissed or permanently resolved. Clarified via
`AskUserQuestion` (×2 rounds): popup fires on page load/navigation (not a
background timer); scope is the whole admin panel, not just Documents;
dismiss = snooze (no DB write, reappears next load), resolve = permanent;
auto-reminder needs no setup (purely derived from overdue
`promised_date`); and - a follow-up question - if a resolved reminder's
student later gets a NEW promised date that also lapses, it should
reactivate automatically (confirmed, not assumed). Recorded as
`TODO.md` REQ-FEAT-025, user said "code it".

**Files:**
- `mobile-app/SUPABASE_STUDENT_REMINDERS.sql` (NEW table
  `student_reminders`: student_id UNIQUE FK, status active/resolved,
  message, resolved_at/by, updated_by/at - RLS + `is_admin_user()`, same
  shape as the other two tables added today). Applied live via Supabase
  MCP; advisor clean.
- `studentService.js` - `getActiveReminders()` combines two sources without
  a nested-join query (kept simple, matching this codebase's existing
  style): fetch all `student_reminders` rows, fetch
  `student_document_followups` rows with a non-null `promised_date`,
  filter client-side for `promised_date < today AND status NOT IN
  (Submitted, Uploaded)`, exclude any already `resolved` in
  `student_reminders`, union in any `active` manual-only reminders, then
  one `.in("id", [...])` query against `students` for display fields
  (name/grno/mobile/mobile2) - avoids a brittle multi-level PostgREST
  nested select for what's fundamentally a small, infrequent query.
  `resolveReminder()` / `setManualReminder()` are plain upserts, same shape
  as the follow-up/note functions. `upsertDocumentFollowup()` got one
  addition: after writing, if `promisedDate` was provided, delete any
  `student_reminders` row for that student with `status = 'resolved'` -
  this is the auto-reactivation rule, implemented as "a (re)promise clears
  old resolutions" rather than tracking promise-versus-resolution
  timestamps, which would have been more precise but added real
  complexity for a case that's rare in practice.
- `src/contexts/ReminderContext.jsx` (NEW) - `ReminderProvider` +
  `useReminders()`. Re-fetches via `usePathname()` from
  `next/navigation` on every route change (not a `setInterval` - matches
  the "page load/navigation, not a timer" decision exactly) and sets
  `popupOpen = true` whenever the fetched list is non-empty. `dismiss()`
  only touches local state (`setPopupOpen(false)`) - deliberately no
  DB write, so the *next* navigation's re-fetch finds the same active
  rows and pops again unprompted. `resolve(studentId)` calls the service
  function then optimistically filters the local list.
- `src/components/ReminderPopup.jsx` (NEW) - the modal: per-item name/GR/
  message, a `tel:` call icon (same pattern as REQ-FEAT-023's follow-up
  call button), a "Resolve" button, and a bottom "Dismiss for now". Only
  renders when `popupOpen && reminders.length > 0`.
- `src/components/ReminderBell.jsx` (NEW) - header badge, renders `null`
  when the list is empty (no empty-state clutter), opens the same popup via
  context so there's exactly one list UI, not two.
- `(dashboard)/layout.js` - wraps the whole shell in `<ReminderProvider>`
  and mounts `<ReminderPopup />` once, as a sibling of the flex layout (not
  inside `<main>`) so the fixed-position modal isn't affected by any page's
  own scroll/overflow styling.
- `Header.jsx` - `<ReminderBell />` added next to, not replacing, the
  pre-existing Notifications bell (`getRecentAdminAlerts` etc.) - that
  system already has its own read/unread semantics and a 90-second poll;
  deliberately kept as a separate, second bell rather than overloading one
  control with two different state machines.
- `StudentNoteBadge.jsx` - new "Also set as a reminder" checkbox (default
  unchecked each time the popover opens) next to Save; when checked, Save
  also calls `setManualReminder(studentId, draft, authUser?.id)` and
  triggers `refresh()` from context so the bell/banner update immediately
  rather than waiting for the next navigation.
- `StudentDocumentsSection.jsx` - the "top of the sheets" banner: an amber
  bar, only rendered when `reminders.length > 0`, whose "View" button calls
  `openPopup()` from the same context - deliberately not a second,
  independent list component, to avoid two places that could drift out of
  sync.
