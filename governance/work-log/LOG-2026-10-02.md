# LOG-2026-10-02 — "add all admin module to admin app": slice 3 (Attendance Overview + reminders)

## Session 1 — Attendance Overview + bulk reminders

### What I set out to do
Continuing yesterday's multi-slice effort (2026-10-01) to bring the Teacher
app's Admin Workspace to parity with the web admin panel. Slice 3: the web
Attendance page's remaining uncovered piece. Checked first and found the
Holidays part of that same web tab needed no new work — it's the same
`school_calendar_events` table already wired up for Year Planning
(SUPABASE_STAFF_APP_SETTINGS_ADMIN.sql, 2026-10-01). The only real gap was
the Overview tab: which class sections have/haven't marked attendance for a
date, plus a "Notify All" bulk reminder to class teachers. Flagged via
AskUserQuestion that this piece was more complex than expected (needs a join
across `student_enrollments`/`classes`/`sections`/`employees`/
`teacher_alerts`, none of which have any `anon` grant at all) before
building it — user confirmed to build it now.

### What I did
1. **New SQL file `mobile-app/SUPABASE_STAFF_APP_ATTENDANCE_OVERVIEW.sql`**
   — two RPCs, same `staff_admin_tier()`-gated pattern (senior_admin/
   management only, matching the web page's admin-only scope):
   - `staff_admin_attendance_overview(p_employee_id, p_date)` — per-section
     marked/partial/not-marked status, joined by `class_id`/`section_id` FKs
     rather than the name-string matching the web's `getStudents()` does
     (the underlying schema is already ID-normalized, so this ended up more
     precise than the web version it's porting, not a looser approximation).
   - `staff_admin_send_attendance_reminders(p_employee_id, p_date,
     p_section_ids)` — same dedup rule as the web's
     `sendBulkAttendanceReminders`: skips a teacher already reminded for
     that exact section today, checked against `teacher_alerts.created_at`
     for the given date.
2. **`staff_admin_service.dart`** — `attendanceOverview` and
   `sendAttendanceReminders` wrapper methods.
3. **New screen `admin_attendance_overview_page.dart`** — date picker,
   per-section status list (color-coded pill: Marked/Partial/Not
   Marked/Empty), "Notify All" action with an unmarked-count confirm dialog
   and a sent/skipped result snack.
4. **Wired into `admin_workspace_home.dart`**'s existing People section,
   next to the pre-existing (class) Attendance tile, gated to
   `_isSeniorOrMgmt`.

**Verified:** `staff_admin_attendance_overview` tested directly via the
Supabase MCP against today's real data — correct per-section marked counts
and class-teacher names came back (e.g. JR.KG/SR.KG/Balvatika/1st/2nd with
real teacher names and accurate 0/18, 44/44, 75/75 etc. counts), confirming
the FK-based join works correctly against production data before any Flutter
code touched it. `flutter analyze` on all changed/new files: 0 errors; only
the same pre-existing unrelated `prefer_const_constructors` notes already
present in `admin_workspace_home.dart` before this session. Not yet
exercised on a real device, and the reminder-sending path specifically
hasn't been fired for real (only read-verified) — worth a deliberate test
send before relying on it to actually nag a teacher.

## Session 2 — Diagnostics viewer (slice 4)

### What I set out to do
Continue the multi-slice port: Diagnostics (the web admin's error-report
inbox fed by both apps' auto-capture + the mobile "Report a Problem" flow -
see CLAUDE.md's REQ-HYG-006 note). Confirmed with the user this was the next
piece before building (simpler than Exams/Attendance Overview, as expected).

### What I did
Checked the web's `admin_get_diagnostic_reports()` RPC and the RLS policies
on `diagnostic_reports`/`diagnostic_settings` first - both tables have
`anon` table grants (the apps' own crash reporters insert directly), but
every read/write policy is keyed on `is_admin_user()`/`admin_has_role()`,
which resolve via `auth.uid()` - NULL for mobile's anon+custom-employee-id
sessions, so RLS blocks the app from reading/writing either table today
despite the grants existing. Same shape of gotcha as yesterday's
impersonation-log wrapper.

1. **New SQL file `mobile-app/SUPABASE_STAFF_APP_DIAGNOSTICS_ADMIN.sql`** —
   four RPCs: `staff_admin_diagnostic_reports`,
   `staff_admin_mark_diagnostic_report`, `staff_admin_get_diagnostics_enabled`/
   `_set_diagnostics_enabled`. Unlike the web's version (which still gives
   `normal_admin` a redacted summary-only view), the mobile version has only
   one branch - full content - since the Admin Workspace is already
   senior_admin/management-gated before this tile even renders, so there's
   no "lesser" mobile caller to redact for. Caught and fixed a real bug
   before applying: `reviewed_by`/`updated_by` turned out to be free-text
   `TEXT` display-name columns (matching the web's own
   `markDiagnosticReport(id, status, reviewedBy)` convention), not FKs to
   `employees` - the first draft stored the raw employee UUID there, fixed
   to look up and store `employees.name` instead, caught by checking
   `information_schema.columns` before applying rather than after.
2. **`staff_admin_service.dart`** — matching Dart methods.
3. **New screen `admin_diagnostics_page.dart`** — enabled/disabled toggle
   switch at the top, report list with status pills (New/Reviewed/Resolved),
   tap-to-expand bottom sheet showing full log entries (pretty-printed
   JSON), inline Mark Reviewed/Resolve actions on New reports.
4. **Wired into `admin_workspace_home.dart`**'s Administration section.

**Verified:** `staff_admin_get_diagnostics_enabled` and
`staff_admin_diagnostic_reports` both tested live via the Supabase MCP
(0 reports currently, consistent with this project's diagnostics-off-by-
default convention). `flutter analyze`: 0 errors, same pre-existing
unrelated lints only. Not yet exercised on a real device, and the
mark-reviewed/resolve and toggle-enabled write paths specifically haven't
been fired for real yet (only the reads were live-verified).
