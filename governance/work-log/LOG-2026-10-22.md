# LOG 2026-10-22 — Batch Management + stop auto-creating batches (REQ-FEAT-021)

## What I set out to do
Fix the admin panel creating a brand-new "batch" every time a student is
added or updated, and give you a proper place to manage batches in
Settings instead.

## What I did
- Found the actual cause: the batch dropdown's default option was secretly
  "+ Start New Batch", so every single Add Student / Edit Student / Update
  Student save created a fresh 1-student batch without you ever picking
  that on purpose. Confirmed this against the real database — batches 6
  through 18 were exactly that: 13 one-student batches, all from today, all
  from editing a single student.
- Changed the dropdown so it defaults to **"— No Batch —"** — nothing gets
  recorded as a batch unless you deliberately pick "+ Start New Batch" or
  an existing one.
- You then clarified the dropdown should really only show up on the
  import/replacement/new-entry tools. So I removed it entirely from the two
  single-student edit screens (Edit Student, and Super Admin's "Update
  Student") — editing one student's details no longer touches batches at
  all, in any way. It still appears on Add Student, Import Students,
  Replace Full Details, and Basic Details Import — the four tools that are
  actually about processing a physical stack of documents together.
- Added a new **Entry Batches** tab in Settings (senior admin / management
  only, same as the other Settings tabs) where you can:
  - create an empty batch ahead of time and give it a name
  - rename or delete a batch
  - open a batch to see exactly which students are in it
  - move a student from one batch to another, or remove them from a batch
  - recompute a batch's student count (in case it ever looks off)
- Deleted the 13 junk batches (6–18) from the live database, after saving
  a full backup of everything in them first.

## Decisions
- You chose to default **all** entry points to "No Batch" at first, then
  corrected it the same session to say the batch picker should only appear
  on import/replacement/new-entry tools — single-student edits drop it
  entirely. What's live now matches your correction, not the first answer.
- You chose to delete the 13 junk batches outright rather than leave them
  for manual cleanup, and to get all four management capabilities (create,
  delete/remove, move, view+recompute) in the new Settings tab.

## Something to know about
The Government Entry report's UDISE/PEN "eligible" list depends on a
student being in *any* batch. Since batches are no longer created
automatically, a student you just edited or added won't show up as
eligible there until you deliberately put them in a batch — and the 13
students whose junk batches got deleted will drop out of that eligible
list too, unless they're already in one of the real batches (1–5). This
is the expected result of switching to manual batch control, but it does
change who shows up on that report.
