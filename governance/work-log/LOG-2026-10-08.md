# LOG 2026-10-08 — MIL (Odia) marksheet percentage fix

## What I set out to do
You reported that in exam marksheet creation, students who don't take MIL
(Odia) — because they're English or Hindi medium, not Odia — were having
their percentage wrongly pulled down by that subject, even though it was
never theirs to take.

## What I did
Looked through how subjects and marksheets actually work in the system
first. Found the real cause: subjects are set up per CLASS, not per
student, so once "MIL (Odia)" is added to a class's subject list, every
student in that class — Odia and non-Odia alike — gets counted as if they
take it. When a teacher correctly leaves MIL blank for a non-Odia student,
the marksheet code was still adding MIL's full marks into that student's
total, with nothing to offset it, so their percentage dropped for a
subject that was never theirs.

I proposed tracking each student's medium directly, but you told me to
keep it simpler: **make MIL (Odia) an "optional" subject.** Now the rule
is just:
- Teacher enters a MIL mark for a student → it counts normally, shown on
  their marksheet (this is the Odia-medium students).
- Teacher leaves it blank → MIL doesn't appear on that student's marksheet
  at all, and its full marks are left out of their total entirely, so their
  percentage is based only on the subjects that actually apply to them.

No new "medium" field was needed anywhere — it just goes by whether a mark
was entered.

## Decisions
- Went with the simpler "optional subject" rule instead of tracking each
  student's medium, per your direction.
- Classified this as a contained change per the project's own process
  (recorded in `governance/planning/TODO.md` as REQ-BUG-072) rather than a
  big architecture change, since nothing about how the app works for any
  other subject changes.

## Files changed (plain meaning)
- A small database change so a subject can be flagged "optional" (default:
  no subject is optional, so nothing changes until you flag one).
- The marksheet-building code (used for the PDF marksheet, the Exams
  report, and the student's own "Official Results" screen in the mobile
  app) now skips an optional subject entirely for a student who was never
  given a mark in it.
- Settings → Subjects in the admin panel now has a star button next to
  each subject — click it to mark that subject "optional" for that class.

## Current state
Database change is live. Code changes are made and pass the project's
automated checks (lint for the web app, analyze for the mobile app). Not
yet clicked through in an actual running browser/app — that's the next
thing to do before calling this fully done.

## Next steps

2. Enter a MIL mark for one Odia-medium student, leave it blank for a
   non-Odia student, and generate that class's marksheet to confirm: the

## Second request this session: TC generation - add surname

### What you asked
You wanted the Transfer Certificate to also show the surname along with
student name, father's name, and mother's name.

### What I found
The student's own name on the TC already includes the surname (it's
built from first name + last name together). But Father's Name and
Mother's Name are stored as just a first name (like "Rajesh" or "Meena")
with no surname at all - so the TC was printing those without any family
name.

### What I did
You confirmed you want the surname auto-added. So now, when a TC is
generated, the student's own surname is automatically added onto
Father's Name and Mother's Name - e.g. "Rajesh Raula" and "Meena Raula" -
unless it's already there (so nobody ever gets it printed twice).

This did NOT touch the separate "upload a spreadsheet of TC data in bulk"
option - that one already lets you type in Father's/Mother's Name exactly
as you want them, so there's nothing to fix there.

### Current state
Code changed and passes the project's checks. Not yet staged/committed -
let me know if you want it pushed like the marksheet fix.
