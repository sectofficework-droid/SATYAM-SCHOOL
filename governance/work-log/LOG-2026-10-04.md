## S3 / app_versions — found two real bugs, fixed both, hit a third issue that's a genuine blocker

User asked "why do you want to upload the apk" when I tried driving Chrome
to the raw AWS S3 console and hit an IAM sign-in wall - good challenge,
answered it, and it surfaced a much better path: Settings -> App Update
already exists in the admin panel for exactly this (presigned upload,
publishes the `app_versions` row), using server-side AWS credentials
neither of us has to touch directly.

**Bug 1 (real, confirmed): `publishAppVersion()` never set `app_versions.app`.**
That column is `NOT NULL` with no default - every publish attempt via this
UI has always failed outright, which is why `app_versions` has been
completely empty since the feature was built (not "unused", "unusable").
The form also had no selector for which app (Teacher/Student/Attendance
Kiosk) an APK belongs to. Fixed: added an app selector - confirmed the
correct values by reading `main_attendance.dart` rather than assuming from
the Gradle flavor name (`UserRole.kiosk`, not `'attendance'`) - threaded
through `getAppVersionHistory`/`getLatestAppVersion`/`publishAppVersion`,
and flavor-prefixed the S3 key since `pubspec.yaml`'s version number is
shared across all three flavors. Committed `712b229`, deployed, verified
live in the browser: selector renders correctly, defaults to Teacher App,
version code correctly computes from (empty) history.

**Bug 2 (real, confirmed): S3 CORS preflight 403.** Filled the form, user
selected the APK, clicked Publish - "Failed to fetch". Live-traced via
Chrome's network panel (not guessed) to an `OPTIONS` preflight to the S3
bucket returning 403. Found `uploadFileToS3Presigned` has exactly one
caller (this feature) - strong evidence this direct-browser-to-S3 path was
never actually exercised end-to-end before. Hypothesis: AWS SDK v3's
default `requestChecksumCalculation: WHEN_SUPPORTED` attaches
`x-amz-checksum-*`/`x-amz-sdk-checksum-algorithm` headers to the presigned
URL, which the bucket's CORS `AllowedHeaders` (configured before this SDK
default existed) doesn't list. Fixed via one-line client config
(`WHEN_REQUIRED` instead), committed `f6e3a5e`, deployed.

**Retried after the fix - partially confirmed, not fully fixed.** Re-checked
network traffic: the checksum headers are confirmed gone from the request.
But the preflight **still returns 403**. So Bug 2's fix was real and
necessary but not sufficient - the bucket's CORS policy itself doesn't
allow PUT from the admin panel's origin at all, independent of headers.
This needs an actual CORS rule added via AWS Console, which neither of us
can do without the user's own AWS login (same boundary as the raw-S3-
console attempt earlier - I won't enter AWS credentials myself). Gave the
user the exact CORS JSON to add. **User said "keep it in to do, will work
later" - explicitly deferred**, filed as `planning\TODO.md` REQ-BUG-060.

# Staff Sunday-absence fix, Teacher app rename/icon, two marks-entry bugs, Teacher v6/v7 shipped to Play Store

## Sunday staff auto-absence bug (REQ-BUG-061)
User reported: kiosk/teacher attendance should never mark staff absent on a
Sunday. Root cause: three separate places that auto-mark staff absent
(`mark-staff-absent` cron, `staff-attendance/sync-absent`, `kiosk-settings`
save) all checked "is there a `working_day` calendar event on this date?"
without checking the event's `applies_to_classes` scope - so a Sunday
working-day override set for one grade's makeup class made the system
treat that Sunday as a working day for every teacher too, not just that
class. Fixed all three to only honor a school-wide (unscoped) override for
staff purposes. Committed `f6f2a7f`, pushed.

Also pushed, unrelated to this bug: `7ccd8f9` (full-codebase security audit
findings recorded in TODO.md, REQ-SEC-012..016+, from earlier today's
session) and `31ce31f` (marksheet PDF DOB removal, pre-existing commit from
before this conversation).

## Teacher app: name + icon
User asked to change the Teacher app's name and logo. Iterated through a
few directions in conversation (navy ribbon on the crest → a fresh
graduation-cap-and-book glyph → crest with a small "T" seal) before the

## Marks-entry bug 1: "marks not saving" (network drops)
User: teachers were having trouble saving marks, believed already fixed,
asked to verify and ship. Traced via `diagnostic_reports` to 504/SSL-
handshake failures dropping the request before it reached Supabase at all
(no matching request in Supabase's own edge logs) - a flaky connection,
not a server/RPC bug. `fetch_exam_marks`/`save_marks_batch` now retry
transient network errors (socket/handshake/timeout/502-504) up to 3 times
with backoff, never retrying a genuine "Not authorized". Save-failure
snackbar now says explicitly when marks were NOT saved due to network vs a
generic error; entered marks stay in the fields either way. Committed
`e4ecc36`.

## Marks-entry bug 2: obtained marks could exceed max_marks
User reported mid-release-prep: Official Exams (and, same bug, Monthly
Test) let a teacher save `marks_obtained` above the exam's configured
max (or negative) - the "/max" suffix was purely decorative, nothing
validated it. Fixed client-side (field turns red immediately, Save All
Marks blocked outright - not silently clamped, since it's almost always a
typo worth the teacher noticing) in both
`teacher_official_exams_page.dart` and `teacher_marks_page.dart`, and
server-side in `save_official_marks_batch`/`save_marks_batch`
(`SUPABASE_FIX_MARKS_EXCEED_MAX.sql`, applied live via Supabase MCP) since
mobile RPCs run as `anon` and the client isn't a trust boundary. Committed
`e8e7d82`.

# Security audit fixes (REQ-SEC-012..016), mobile resilience & admin workspace parity

## Security audit fixes & API hardening
- **REQ-SEC-012**: Enforced admin session authentication (`requireAdminSession`) on `kiosk-settings`, `staff-attendance/delete`, and `staff-attendance/sync-absent` API routes using shared `apiAuth.js` and `authedFetch.js` helpers.
- **REQ-SEC-014**: Required and verified mobile session tokens (`verify_mobile_session`) on all 6 server-side PDF report routes (`attendance`, `bonafide`, `id-card`, `marksheet`, `salary`, `tc`) in `reportsServerAuth.js`, preventing unauthorized PII access.
- **REQ-SEC-015**: Escaped student fields in `tcGenerator.js` (`esc(...)`) to prevent stored XSS.
- **REQ-SEC-016**: Migrated `fetchEmployeeAttendance` from direct table access to session-gated RPC `fetch_my_employee_attendance` (`SUPABASE_FIX_EMPLOYEE_ATTENDANCE_SESSION_RPC.sql`).
- **REQ-BUG-015**: Invalidated tokenless cached sessions on startup in `AuthService` so users land on login and obtain active session tokens.
- **REQ-BUG-062**: Restricted employee salary column and aggregates on web Report page to management role only (`getEmployeesForReport(isMgmt)`).
- **REQ-BUG-063**: Added `_firstRow` helper with empty-list guards across kiosk RPC call sites in `supabase_service.dart` and `staff_admin_service.dart`.

## Mobile error handling, bug fixes & resilience
- **REQ-BUG-064**: Reset `_embeddings` and `_poses` on error in `face_enroll_capture_page.dart` to prevent RangeError infinite loops.
- **REQ-BUG-066**: Blocked silent save failures in teacher attendance, marks, and official exams on missing/stale session tokens, failing loudly with error snackbars and wrapping batch saves in try/catch.
- **REQ-BUG-067**: Disposed `TextEditingController` instances before clearing maps and on page disposal in `teacher_marks_page.dart` and `teacher_official_exams_page.dart`.
- **REQ-BUG-069**: Added robust try/catch blocks, error states, and retry UI across all student screens and teacher mutation handlers. Implemented optimistic UI rollback in `teacher_syllabus_page.dart`.
- **REQ-BUG-070**: Standardized `teacher_notices_page.dart` on shared `NoticeCard` widget, restoring tap-to-expand functionality.
