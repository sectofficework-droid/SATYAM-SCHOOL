2. **Added 2-Up Landscape Sheet Engine (`generateSchoolLeavingCertificateSheet`)**:

6. **Automatic Attendance Lateness Recalculation**:
   - Diagnosed reason why report showed old lateness: `is_late` and `late_minutes` were permanently saved at the moment of check-in against the previous 7:25 AM setting.
   - Recalculated today's 17 attendance records against 7:30 AM + 5 min grace, converting 7 false lates to "On Time" (0 late arrivals today).
   - Enhanced `/api/kiosk-settings` and `SUPABASE_FIX_SAVE_KIOSK_SETTINGS.sql` to automatically recalculate that day's attendance in real-time when punch timings change.
7. **Automated Absent Marking on Cutoff & Page Sync**:
   - Diagnosed why absent was not showing after setting 8:20 AM cutoff: absent rows had not been generated yet (cron ran at 2:30 PM, page refresh did not trigger absent evaluation).
   - Inserted `'A'` (Absent) records for 10 unpunched active staff for today (17 Present, 10 Absent, total 27).
   - Created `/api/staff-attendance/sync-absent` and connected it to `reportService.js` (on report view/refresh) and `/api/kiosk-settings` (on setting save).
8. **Verified**:

   - Production API `/api/staff-attendance/sync-absent` returned 200 OK.
   - `npm run build`: 49/49 routes compiled and static-generated cleanly with exit code 0.

## Session 3 — Closing the last 3 admin-panel bugs (decisions asked one by one)

### What I set out to do
User asked to go through REQ-BUG-025/030/034 (left open at the end of
Session 2 because each needed a product/schema decision) one at a time:
ask, get an answer, fix that one, then move to the next.

### What I did
- **REQ-BUG-025** — Asked whether a second same-month payroll run should
  overwrite, accumulate, get its own row (schema change), or be blocked
  with a per-employee warning. User chose **block and warn**.
  `employee/page.js`'s `handleGenerate()` now queries `salary_payments`
  for the target month first, skips only employees who already have a row
  there, alerts the admin by name for those, and still pays everyone else
  in the batch instead of the whole insert failing on one collision.
- **REQ-BUG-030** — Asked whether to add a DB-level uniqueness guard or
  accept the risk. User chose **add the guard**. Checked
  `pg_constraint`/`pg_indexes` via Supabase MCP first — both
  `student_enrollments_enrollment_no_key` (UNIQUE enrollment_no) and
  `student_enrollments_academic_year_id_class_id_section_id_ro_key`
  (UNIQUE academic_year_id, class_id, section_id, roll_no) **already
  existed** in production (confirmed no duplicate rows exist either, via
  direct query, before concluding this). So no migration was needed — the
  real gap was that `studentService.addStudent` never retried on the
  collision the DB was already correctly rejecting. Rewrote the enrollment
  insert (previously a single attempt) into a bounded retry loop (5
  attempts, 3 if roll_no was manually entered) that regenerates the next
  enrollment/roll number and retries only on Postgres `23505`
  (unique_violation); any other error still compensates (deletes the
  just-inserted `students` row) and throws immediately, same as before.
- **REQ-BUG-034** — Asked whether to migrate uniformFees/oldStudentDiscount
  to the DB or document the risk. User chose **migrate**. Checked the
  schema first: `fee_structures` already has `uniform_amount` and
  `old_student_discount` columns, and `saveFeeStructuresForYear` (already
  called from Settings → Fee Structure) already writes both — so again no
  migration was needed, only a reader. Added
  `settingsService.getCurrentYearPromotionConfig()` (mirrors the existing
  `getCurrentYearClassFees()` pattern: resolves the current academic year,
  reads `fee_structures`, returns `{ uniformByClass, oldStudentDiscount }`,
  falls back to `{}`/1000 on no data or a query error, logging the error
  instead of swallowing it). `student/page.js`'s `PromoteModal` now fetches
  this on mount instead of reading `useStore(s => s.uniformFees /
  s.oldStudentDiscount)`. Removed the two store fields/setters from
  `store.js` and their now-dead writes from `settings/page.js`'s
  `FeeStructureTab.save()` (grepped the whole `src/` tree first to confirm
  nothing else still read them) rather than leave unused plumbing behind.
